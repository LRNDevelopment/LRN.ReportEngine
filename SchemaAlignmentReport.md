# Schema alignment with production

Generated by `sql/align_with_production.py`. Re-run it after any mapping change.

**Baseline:** `sql/Existing_LineLevel_ClaimLevel_DATA.sql` — the `LineLevelData` /
`ClaimLevelData` schema already running in production for 12 labs. Every column it declares is
reproduced verbatim: same name, same type, same nullability. Nothing is renamed, retyped,
narrowed or dropped.

**On top of that**, a column is added when either source below declares it and production
does not:

- `LRN.BillingFrequencyWorker/Schemas/LineLevel.schema.json` / `ClaimLevel.schema.json`
- this worker's own lab mapping (`Schemas/LabMappings/*FieldMappings.json`)

**A production column this worker has no mapping for is kept and loads NULL.** Those are the
ones to check: each is a column production expects that we are not currently populating.
